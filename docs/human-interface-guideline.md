# Apple Human Interface Guidelines (HIG) for iOS / Cupertino

このドキュメントは、iOS アプリ（Cupertino ベース）の UI/UX 設計時に参照する Apple HIG のガイドラインを要約したものです。
前半は汎用的な HIG、後半はこのアプリの UI 比較検討のインプットとなる情報の視覚的表現を記載しています。

> **情報源**: Apple Human Interface Guidelines（2024年時点）に基づく。最新の変更点は [公式サイト](https://developer.apple.com/design/human-interface-guidelines/) を参照。

---

## 1. デザインの基本原則

| 原則 | 概要 |
| :--- | :--- |
| **明確さ (Clarity)** | テキストは読みやすく、アイコンは理解しやすく、操作は曖昧さなく行える。装飾を排し、機能性を際立たせる |
| **敬意 (Deference)** | UI はコンテンツを引き立たせるもの。UI 自体が主張しすぎず、ユーザーがコンテンツに集中できるデザイン |
| **深さ (Depth)** | 視覚的な階層やレイヤーで情報構造を伝える。モーダルやナビゲーション遷移で「今どこにいるか」を直感的に理解させる |
| **一貫性 (Consistency)** | システム標準の UI コンポーネント・アイコン・用語・操作方法を踏襲し、ユーザーが使い方を推測しやすくする |

## 3. コンポーネント別ガイド

### 3.1 Buttons（ボタン）

#### 種類と使い分け

| スタイル | Flutter | 使用場面 | 視覚的特徴 |
|---------|---------|---------|-----------|
| **Filled** | `CupertinoButton.filled` | 画面内の最も重要なアクション（1画面1つが理想） | アクセントカラー背景、白テキスト |
| **Tinted** | カスタム実装 | Filled より重要度が低い主要アクション | 薄いアクセントカラー背景 |
| **Gray** | カスタム実装 | 補助的なアクション | グレー背景 |
| **Plain** | `CupertinoButton` | テキストリンク的なアクション | テキストのみ（アクセントカラー） |

#### ガイドライン

- **使うべき場面**: ユーザーが明示的にアクションを実行する場面
- **推奨**: ラベルは動詞から始める（「生成する」「コピーする」）
- **推奨**: 1画面に Filled ボタンは1つに絞る
- **推奨**: 破壊的アクション（削除等）は赤色 + 確認ダイアログ
- **避けるべき**: 複数の Filled ボタンを1画面に並べる（優先順位が不明確）
- **避けるべき**: 「OK」「はい」など曖昧なラベル（具体的なアクション名が望ましい）

---

### 3.2 Toggles / Switches（トグル / スイッチ）

**Flutter**: `CupertinoSwitch`

#### ガイドライン

- **使うべき場面**: 2択のオン/オフ切り替え。切り替え即座に効果が反映される設定
- **推奨**: スイッチの左側にラベルを配置する
- **推奨**: ラベルは ON 状態を説明する肯定文にする（例: 「大文字を含む」）
- **推奨**: デフォルト値は「最も安全」または「最も一般的」な選択肢
- **推奨**: 切り替え時に「保存」ボタン不要（即時反映）
- **避けるべき**: 3つ以上の選択肢にスイッチを使う → セグメントコントロールを検討
- **避けるべき**: 否定形のラベル（「通知を無効にする」→「通知を受け取る」に変更）

---

### 3.3 Sliders（スライダー）

**Flutter**: `CupertinoSlider`

#### ガイドライン

- **使うべき場面**: 連続的な範囲内の値を調整する場面（音量、明るさ、文字数等）
- **推奨**: 現在の値をスライダーの近くにリアルタイム表示する
- **推奨**: 最小値・最大値のラベルを表示する（オプション）
- **推奨**: ドラッグ中にリアルタイムで結果をプレビューする
- **避けるべき**: 正確な値の入力が必要な場面 → テキストフィールドを使う
- **避けるべき**: 選択肢が少数（2〜5個）の場面 → セグメントコントロールを使う
- **避けるべき**: 非線形なスケールを線形スライダーで表現する

---

### 3.4 Action Sheets（アクションシート）

**Flutter**: `CupertinoActionSheet` / `showCupertinoModalPopup`

#### ガイドライン

- **使うべき場面**: ユーザーのアクションに応じて2つ以上の選択肢を提示する場面
- **推奨**: 画面下部からスライドアップで表示する
- **推奨**: 「キャンセル」ボタンはシート最下部に独立して（区切り線の下に）配置する
- **推奨**: 破壊的アクション（削除等）は赤色テキストで表示する
- **推奨**: タイトルやメッセージでコンテキストを説明する
- **避けるべき**: 2択の確認 → アラートを使う
- **避けるべき**: 選択肢が多すぎる（7個以上）
- **避けるべき**: ユーザーのアクションなしに自動表示する

---

### 3.5 Alerts（アラート）

**Flutter**: `CupertinoAlertDialog` / `showCupertinoDialog`

#### ガイドライン

- **使うべき場面**: 重要な情報の通知、破壊的アクションの確認
- **推奨**: タイトルは簡潔に（1文）、メッセージは必要最小限
- **推奨**: ボタンは2つ以下。3つ以上ならアクションシートを使う
- **推奨**: キャンセル＝左/下、デフォルトアクション＝右/上
- **推奨**: 破壊的アクションのボタンは赤色で左側に配置
- **推奨**: ボタンラベルは具体的なアクション名（「OK」ではなく「削除する」）
- **避けるべき**: 情報提供だけのアラートを頻繁に表示する（フローを中断する）
- **避けるべき**: 長文のメッセージ

---

### 3.6 Sheets / Modals（シート / モーダル）

**Flutter**: `showCupertinoModalPopup` / モーダルルート

#### 種類

| 種類 | 使用場面 | 特徴 |
|------|---------|------|
| **Full-screen modal** | 複雑なタスク | 画面全体を占有。ナビゲーションバーに完了/キャンセル |
| **Sheet（半モーダル）** | 簡単なタスク、追加情報 | 画面下部から表示。スワイプで閉じ可能 |
| **Alert** | 重要な確認、エラー通知 | 画面中央に表示。背景ディム |
| **Action Sheet** | 複数の選択肢 | 画面下部からスライドアップ |

#### ガイドライン

- **使うべき場面**: 現在のコンテキストに関連するサブタスクを完了させる場面
- **推奨**: ナビゲーションバーに「完了」や「閉じる」ボタンを配置する
- **推奨**: 背景をディム（暗く）してモーダルであることを視覚的に示す
- **推奨**: スワイプダウンで閉じられるようにする（iOS 標準動作）
- **推奨**: 未保存の変更がある場合、閉じる前に確認ダイアログを表示する
- **避けるべき**: モーダルの上にさらにモーダルを重ねる（2段階以上のネスト）
- **避けるべき**: メインナビゲーションにモーダルを使う（push ナビゲーションを使う）

---

### 3.7 Lists（リスト）

**Flutter**: `CupertinoListSection` / `CupertinoListTile`

#### スタイル

| スタイル | 用途 | 外観 |
|---------|------|------|
| **Inset Grouped** | 設定画面、フォーム | 角丸のグループ化されたセクション（Settings 風） |
| **Plain** | データ一覧 | 画面幅いっぱいのフラットなリスト |

#### ガイドライン

- **使うべき場面**: 設定画面、一覧表示
- **推奨**: 設定画面には Inset Grouped スタイルを使用する
- **推奨**: セクションにヘッダーとフッターを付けてグループの意味を説明する
- **推奨**: リスト項目の右側にアクセサリ（ディスクロージャーインジケーター `>` 等）を配置
- **避けるべき**: リスト項目の高さが不均一で読みにくいレイアウト

---

### 3.8 Progress / Activity Indicators（プログレス / アクティビティインジケーター）

#### 種類と使い分け

| 種類 | Flutter | 使用場面 |
|------|---------|---------|
| **Indeterminate spinner** | `CupertinoActivityIndicator` | 所要時間が不明な場合 |
| **Determinate progress bar** | カスタム実装 | 進捗率が分かる場合 |
| **Pull-to-refresh** | `CupertinoSliverRefreshControl` | リスト更新 |

#### ガイドライン

- **推奨**: 1秒以上かかる操作にインジケーターを表示する
- **推奨**: 進捗率が分かる場合はプログレスバーを使用する
- **推奨**: 可能な限りコンテンツのプレースホルダー（スケルトン）を表示する
- **避けるべき**: 0.5秒未満の操作にインジケーターを表示する（チラつきの原因）
- **避けるべき**: インジケーターだけで、何を待っているか説明しない

---

### 3.9 Segmented Controls（セグメントコントロール）

**Flutter**: `CupertinoSlidingSegmentedControl`

#### ガイドライン

- **使うべき場面**: 2〜5個の相互排他的な選択肢を切り替える場面
- **推奨**: セグメント数は5個以下にする
- **推奨**: 選択の切り替えは即座に効果を反映する
- **推奨**: `CupertinoSlidingSegmentedControl` でモダンなスタイルにする
- **避けるべき**: セグメント内のテキストが長すぎて収まらない
- **避けるべき**: 6個以上のセグメント → タブバーやリストを検討
- **避けるべき**: ナビゲーション（画面遷移）目的での使用 → タブバーを使う

## 4. 色

### セマンティックカラー（推奨）

モード対応で自動的にライト/ダークを切り替える。

| カラー名 | 用途 |
|---------|------|
| `label` | 主要テキスト |
| `secondaryLabel` | 補助テキスト |
| `tertiaryLabel` | 第三レベルテキスト |
| `systemBackground` | 画面背景 |
| `secondarySystemBackground` | グループ内背景 |
| `systemGroupedBackground` | グループテーブル背景（Settings 風） |
| `secondarySystemGroupedBackground` | グループ内セル |
| `separator` | 区切り線 |
| `systemFill` 〜 `quaternarySystemFill` | フィル色（4段階） |

### システムカラー（アクセントカラー群）

| カラー名 | 主な用途 |
|---------|---------|
| `systemRed` | エラー、削除、破壊的アクション |
| `systemOrange` | 警告、注意 |
| `systemYellow` | 注意（軽度） |
| `systemGreen` | 成功、完了、安全 |
| `systemBlue` | インタラクティブ要素、リンク、デフォルトアクセントカラー |
| `systemGray` 〜 `systemGray6` | 無彩色バリエーション |

### ガイドライン

- **推奨**: セマンティックカラーを使い、ダークモード/ライトモードに自動対応させる
- **推奨**: 色だけで情報を伝えない（色覚多様性への配慮。テキスト・アイコン・形状を併用）
- **推奨**: コントラスト比は WCAG AA 基準（4.5:1 以上）を確保
- **推奨**: カスタムカラーを使う場合は、ライト/ダーク両方のバリエーションを定義する
- **避けるべき**: ハードコードされた RGB 値をダークモード対応なしで使用する

## 5. タイポグラフィ

### テキストスタイル（Dynamic Type 対応）

iOS では San Francisco フォントファミリーが標準。

| テキストスタイル | デフォルトサイズ (pt) | ウェイト | 用途 |
|----------------|---------------------|---------|------|
| `largeTitle` | 34 | Regular | 画面タイトル（大） |
| `title1` | 28 | Regular | セクションタイトル |
| `title2` | 22 | Regular | サブタイトル |
| `title3` | 20 | Regular | 小タイトル |
| `headline` | 17 | Semibold | 見出し（太字） |
| `body` | 17 | Regular | 本文テキスト |
| `callout` | 16 | Regular | 吹き出し、補足テキスト |
| `subheadline` | 15 | Regular | 小見出し |
| `footnote` | 13 | Regular | 脚注、補足情報 |
| `caption1` | 12 | Regular | キャプション |
| `caption2` | 11 | Regular | 小キャプション |

### ガイドライン

- **推奨**: Dynamic Type に対応し、ユーザーの文字サイズ設定を尊重する
- **推奨**: テキストスタイル名を直接使用し、フォントサイズをハードコードしない
- **推奨**: 重要な情報は `headline` 以上、本文は `body` を使用
- **推奨**: 太字テキスト設定（Bold Text）にも対応する
- **避けるべき**: 1つの画面で多数の異なるフォントサイズを使用し、視覚的階層が不明確になる
- **避けるべき**: 細すぎるフォントウェイト（Ultralight 等）を小サイズで使用する

## 6. フィードバック

### 触覚フィードバック（Haptic Feedback）

| タイプ | 用途 | Flutter |
|-------|------|---------|
| **Impact (Light)** | 軽いタッチアクション | `HapticFeedback.lightImpact()` |
| **Impact (Medium)** | 中程度のアクション（コピー、トグル切り替え） | `HapticFeedback.mediumImpact()` |
| **Impact (Heavy)** | 重要なアクション完了 | `HapticFeedback.heavyImpact()` |
| **Selection** | 選択変更（ピッカー、セグメントコントロール） | `HapticFeedback.selectionClick()` |
| **Notification (Success)** | 成功フィードバック | 要プラットフォームチャネル |
| **Notification (Warning)** | 警告フィードバック | 要プラットフォームチャネル |
| **Notification (Error)** | エラーフィードバック | 要プラットフォームチャネル |

### 視覚的フィードバック

| フィードバック | 用途 | 実装例 |
|-------------|------|-------|
| **ハイライト** | ボタンタップ時 | iOS 標準のタップハイライト |
| **一時的テキスト** | 操作完了通知 | 「コピーしました」テキスト表示 → 自動消滅 |
| **チェックマーク** | 完了通知 | アニメーション付きチェックマーク |
| **シェイク** | エラー入力 | 横方向のシェイクアニメーション |
| **色の変化** | 状態変更 | 背景色の遷移アニメーション |

### ガイドライン

- **推奨**: アクションの重要度に応じた強度のハプティクスを選択する
- **推奨**: 視覚的フィードバックと触覚フィードバックを組み合わせる
- **避けるべき**: すべてのタッチに触覚フィードバックを付ける（過剰で意味が薄れる）
- **避けるべき**: 触覚フィードバックだけに頼る（視覚フィードバックも必須）

## 7. レイアウト

### 基本原則

| 原則 | 説明 |
|------|------|
| **セーフエリアの尊重** | Dynamic Island、ホームインジケーター、ステータスバーの領域にコンテンツを配置しない |
| **マージンとパディング** | 標準的な左右マージンは 16pt（コンパクト幅）、20pt（レギュラー幅） |
| **タッチターゲット** | 最小 44×44pt のタッチ領域を確保 |
| **視覚的階層** | 情報の重要度に応じてサイズ・色・配置を使い分ける |
| **一貫した間隔** | 8pt グリッドシステムを基本とした間隔設計 |

### iOS の人間工学

| ゾーン | 特徴 | 適した配置 |
|-------|------|-----------|
| **画面上部** | 最も視認性が高い | 重要な情報の表示 |
| **画面中央** | 指が届きやすい | 頻繁に操作する設定コントロール |
| **画面下部** | 最も指が届きやすい | 最頻アクション（主要ボタン） |

### ガイドライン

- **推奨**: 柔軟なレイアウトで様々な画面サイズに対応する
- **推奨**: コンテンツを画面端いっぱいに広げず、適切なマージンを設ける
- **避けるべき**: 固定の幅/高さをピクセルで指定する
- **避けるべき**: ノッチや Dynamic Island の領域にインタラクティブ要素を配置する

## 8. アクセシビリティ

### 4つの柱

| 柱 | 内容 |
|----|------|
| **知覚可能** | 情報を複数の方法で提示（視覚 + テキスト + 触覚） |
| **操作可能** | すべての機能にアクセスできる操作手段を提供 |
| **理解可能** | 予測可能で一貫した動作、平易な言葉 |
| **堅牢** | 支援技術（VoiceOver 等）で正しく解釈される |

### 具体的な対応事項

| 項目 | ガイドライン |
|------|------------|
| **VoiceOver** | すべての UI 要素にアクセシビリティラベルを付与。意味のある順序で読み上げ |
| **Dynamic Type** | テキストスタイルを使用し、ユーザー設定のフォントサイズに追従 |
| **Bold Text** | 太字テキスト設定 ON 時に適切に反応 |
| **色のコントラスト** | WCAG AA 基準（4.5:1 以上、大文字は 3:1 以上）を満たす |
| **Reduce Motion** | モーション軽減設定に対応し、アニメーションを簡略化 |
| **色覚多様性** | 色だけで情報を伝えない。形状・テキスト・パターンを併用 |

### ガイドライン

- **推奨**: 開発初期からアクセシビリティを組み込む（後付けしない）
- **推奨**: VoiceOver で全画面をテストする
- **避けるべき**: カスタムウィジェットでアクセシビリティのセマンティクスを省略する

## 9. パターン

### 9.1 モダリティ

- **推奨**: モダリティは必要な場合のみ使用する（常に最善ではない）
- **推奨**: モーダル表示時に明確な閉じ方を提供する（完了ボタン、キャンセルボタン、スワイプ）
- **推奨**: モーダルのタイトルでタスクの目的を明示する
- **避けるべき**: 複数のモーダルを同時に表示する
- **避けるべき**: 情報表示のみの目的でモーダルを使う（モーダルはアクションが伴うべき）

### 9.2 ナビゲーション

| 種類 | 用途 | Flutter |
|------|------|---------|
| **階層型** | 詳細に掘り下げていく | `Navigator.push` / `go_router` |
| **フラット** | 同階層のセクション切り替え | `CupertinoTabBar` |
| **モーダル** | 一時的なタスクの完了 | モーダルルート |

- **推奨**: ナビゲーションバーに戻るボタン（`<`）を配置する
- **推奨**: タブバーは 3〜5 個のタブに収める
- **推奨**: 画面遷移アニメーションは iOS 標準（右からスライド）に従う
- **推奨**: Large Title スタイルのナビゲーションバーをトップレベル画面で使用する
- **避けるべき**: 深すぎるナビゲーション階層（3〜4 階層が限度）

### 9.3 エラーハンドリング

| エラーの深刻度 | 表示方法 | 例 |
|-------------|---------|-----|
| **致命的** | アラートダイアログ | ネットワーク接続なし、認証エラー |
| **重要** | インラインメッセージ | フォームバリデーションエラー |
| **軽微** | インラインヒント | 入力形式の提案 |
| **情報** | バナー / トースト | オフラインモードの通知 |

- **推奨**: 「何が起きたか」+「どうすれば解決できるか」を含める
- **推奨**: バリデーションエラーはフィールドの近くにインラインで表示する
- **推奨**: エラー時に入力済みのデータを保持する（ユーザーの入力を消さない）
- **推奨**: 可能な限りエラーを予防する設計にする（バリデーション、入力制限等）
- **避けるべき**: 技術的なエラーメッセージをユーザーに表示する
- **避けるべき**: 赤色のみでエラーを示す（テキスト説明を併用すべき）

### 9.4 設定画面

- **推奨**: アプリ内に設定画面を設ける（iOS 設定アプリへの遷移は補助的に）
- **推奨**: Inset Grouped スタイルのリストを使用する（Settings.app 風）
- **推奨**: トグル設定は即座に反映し、保存ボタンは不要
- **推奨**: セクションごとにグループ化し、ヘッダーとフッター説明を付ける
- **推奨**: デフォルト値は最も一般的で安全な値にする
- **避けるべき**: 設定変更後に「保存」ボタンが必要（トグルは即時反映が標準）

### 9.5 ローディング状態

| 所要時間 | 対応 |
|---------|------|
| 0.1 秒以下 | フィードバック不要 |
| 0.1 秒〜1 秒 | ボタンの無効化やハイライトで十分 |
| 1 秒〜10 秒 | スピナー（`CupertinoActivityIndicator`）を表示 |
| 10 秒以上 | プログレスバー + テキスト説明を表示 |

- **推奨**: スケルトンスクリーンでコンテンツの配置を事前に示す
- **推奨**: 可能であればオプティミスティック UI（即座に結果を反映し、バックグラウンドで処理）
- **避けるべき**: 全画面ブロッキングスピナー

## 10. 情報の視覚的表現

### 10.1 ステータス表示の方法

| 表現方法 | 用途 | 実装例 |
|---------|------|-------|
| **バッジ** | 未読数、通知数 | アイコン右上に赤い丸と数字 |
| **ドットインジケーター** | 新着通知 | アイコン右上に小さな青い丸 |
| **テキストラベル** | 明示的なステータス | 「完了」「処理中」「エラー」 |
| **色付きタグ** | カテゴリやステータス | 色付きの角丸矩形にテキスト |
| **アイコン** | 視覚的なステータス表示 | チェックマーク、警告アイコン |

### 10.2 レベル / 段階の表現方法

| 表現方法 | 用途 | 特徴 |
|---------|------|------|
| **セグメントバー** | 段階的なレベル表示 | 離散的な段階（3〜5段階）を視覚的に区別。色 + テキスト併用が容易 |
| **プログレスバー** | 連続的な進捗率（0〜100%） | 連続値の表現に適する。具体的な割合が分かる場面向け |
| **ゲージ** | 測定値の表示 | 円形や半円形。バッテリー残量、ストレージ使用量など |
| **色のグラデーション** | 連続的なレベル | 赤→黄→緑の段階表示。直感的だがアクセシビリティに注意 |
| **テキストのみ** | シンプルなレベル表示 | 「弱い」「強い」等のテキスト + 色。最もアクセシブル |
| **星評価** | 5段階評価 | レビュー評価向け。レベル表示には不向き |

### レベル表現のガイドライン

- **推奨**: 色 + テキスト + 形状の3要素で伝える（アクセシビリティ）
- **推奨**: 段階的な色変化は直感的な意味に合わせる（赤=危険/弱い、緑=安全/強い）
- **推奨**: 段階数は 3〜5 が適切（多すぎると区別がつかない）
- **推奨**: 現在のレベルだけでなく、改善方法も提示する
- **避けるべき**: 色だけでレベルを表現する

### 10.3 インジケーターの種類と使い分け

| インジケーター | Flutter | 使用場面 |
|-------------|---------|---------|
| **Activity Indicator（スピナー）** | `CupertinoActivityIndicator` | 不定期間のローディング |
| **Progress Bar（進捗バー）** | カスタム実装 | 定量的な進捗表示 |
| **Page Control（ページドット）** | カスタム / パッケージ | 複数ページ間の現在位置 |
| **Refresh Control** | `CupertinoSliverRefreshControl` | Pull-to-refresh |
