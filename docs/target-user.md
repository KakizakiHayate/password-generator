# ターゲットユーザー定義書

## 概要

このドキュメントは、パスワード生成アプリのターゲットユーザーと提供価値を定義したものです。
AI による Issue 作成、UI/UX 提案、機能提案時に参照し、ターゲットに合った一貫性のある意思決定を行うために使用します。

---

## ターゲットユーザー

### 基本属性

| 項目 | 内容 |
|------|------|
| 年代 | 20〜40代（働いている世代） |
| 性別 | 不問（性別に偏らないプロダクト） |
| ITリテラシー | 低〜中。スマホは日常的に使うが、1Password や Bitwarden のような専用管理ツールは「面倒」「難しそう」で使っていない |
| 利用デバイス | iPhone（iOS 17.0+） |
| 検索行動 | App Store で「パスワード生成」「パスワード作成」と検索してたどり着く |

### 導出根拠（競合レビュー分析より）

このターゲット設定は、App Store の競合アプリレビューから以下の傾向を読み取って導出したものです。

- 「パスワード生成」で検索するユーザーは、Apple 純正のパスワード自動生成（Safari 内で自動提案される機能）では対応できない**特定の状況**を抱えている
- 競合アプリのレビューで「シンプルで助かる」「他のアプリはURL やID の登録を求めてくるが、これは純粋にランダム文字列を作ってくれるだけで良い」といった声が多く、**軽量さ・手軽さ**を求めている
- 1Password 等の総合管理ツールのレビューでは「設定が複雑」「そこまでの機能はいらない」という声があり、**管理ツールとパスワード生成の間に隙間**がある

### ペルソナ例

#### ペルソナ A: 会社員（30代・セキュリティ意識はあるが面倒くさがり）

> 32歳の営業職。社内システムのパスワードを「英大文字・小文字・数字・記号を各1文字以上、12文字以上」で3ヶ月ごとに変更するルールがある。
> 毎回パスワードを考えるのが面倒で、つい似たようなパスワードを使い回してしまう。
> 1Password は会社で推奨されているが、プライベートでまで使うのは面倒。サクッと安全なパスワードを作ってコピーできればそれでいい。

#### ペルソナ B: 親世代にアプリを教える側（20代）

> 26歳のIT企業勤務。親（60代）が新しいWebサービスに登録するたびに「パスワードどうすればいい？」と聞いてくる。
> 親にパスワードマネージャーを教えるのは難しいので、「このアプリで作って、メモ帳に控えて」と言える、とにかく簡単なアプリが欲しい。
> 紛らわしい文字（oと0、lと1）が除外できると、親が手書きで控えるときに間違えなくて助かる。

#### ペルソナ C: 複数サービスを使い分けるフリーランス（30代）

> 35歳のフリーランスデザイナー。クライアントごとに異なるツール（Slack, Notion, Figma, AWS等）のアカウントを持っている。
> 新規アカウント作成の頻度が高く、サービスごとに「使える記号が違う」のが地味にストレス。
> 「このサービスは@と#だけ使える」みたいな制約に合わせて記号を選べるアプリがあれば助かる。

## ユーザーが抱える課題

### 1. Apple 純正では対応できない場面がある

| シーン | 具体的な課題 |
|--------|------------|
| **ブラウザ外でのパスワード作成** | Safari以外のアプリ内や、メールで送られたパスワード変更リンクでは、Apple の自動生成が出ないことがある |
| **厳格なパスワードポリシー** | 「記号は!@#のみ使用可」「先頭は英字」など、企業・サービス固有のルールに Apple 純正は対応できない |
| **手書きメモ用のパスワード** | oと0、lと1が混在するパスワードは、紙に控える際に判別できない |

### 2. 既存のパスワード生成アプリへの不満

| 不満点 | レビューでの声（要約） | 該当アプリ |
|--------|---------------------|-----------|
| **広告が邪魔** | 「広告を見るか課金するか脅される」 | Password Generator X |
| **設定が毎回リセットされる** | 「デフォルトが20文字で毎回直すのが面倒」 | Strong Password Maker 他 |
| **紛らわしい文字を除外できない** | 「oO0やlI1が入るとメモ時に困る」 | 大半のアプリ |
| **特殊文字を個別に選べない** | 「サイトで使える記号が限られているのに全記号入る」 | 大半のアプリ |
| **UIが古い・放置されている** | 「4年間アップデートなし」 | #1 Password Generator 他 |
| **パスワード管理ツールが重い** | 「そこまでの機能はいらない、生成だけでいい」 | 1Password, Bitwarden 等 |

### 3. 「強度」の可視化がない

| 課題 | 詳細 |
|------|------|
| **自分のパスワードが安全かわからない** | 生成されたパスワードの強度が数値やビジュアルで表示されない（日本語アプリ全般） |
| **「なぜこの長さが必要か」が伝わらない** | 解読推定時間がないため、16文字と8文字の差が直感的にわからない |

## 競合との差別化

### このアプリの強み

| # | 強み | 詳細 |
|---|------|------|
| 1 | **広告なし・完全無料** | セキュリティツールに広告を入れると信頼を損なう。競合の最大不満を根本から排除 |
| 2 | **設定の自動保存** | 前回の設定を覚えている。毎回設定し直す必要がない。競合の半数以上が未対応 |
| 3 | **紛らわしい文字の除外** | oO0, lI1 をワンタップで除外。手書きメモ派や親世代に実用的 |
| 4 | **記号のカスタム選択** | サイトごとの記号制約に対応。「!@#だけ使いたい」が実現できる |
| 5 | **強度の可視化** | エントロピーと解読推定時間を表示。日本語アプリにはほぼ存在しない |
| 6 | **モダンなCupertino UI** | iOSネイティブ風の洗練されたデザイン。既存アプリのUI老朽化との明確な差 |

### 競合アプリとの位置づけ

| アプリ | 特徴 | このアプリとの違い |
|--------|------|-------------------|
| Apple純正パスワード | Safari/アプリ内で自動生成 | 単体ツールとして使えない。記号カスタムも不可 |
| かんたんパスワード生成 | シンプル、広告少なめ | 強度表示なし、記号カスタムなし、UIが古い |
| かんたんシンプル作成 | 紛らわしい文字除外あり | ユーザー追跡あり（プライバシー面で不利） |
| KeyForge | 保存しない設計 | 強度表示なし、記号カスタムなし |
| Password Generator X | 多機能 | 広告への不満が最大。レビューで酷評多数 |
| 1Password / Bitwarden | 総合管理ツール | 生成だけしたい層にはオーバースペック |

## 提供するコアバリュー

### ユーザーに届けたい3つの価値

| # | 価値 | 説明 |
|---|------|------|
| 1 | **速さ** | 開いて1秒で生成完了。設定は前回のまま。コピーもワンタップ |
| 2 | **柔軟さ** | 文字種・記号・除外文字を細かく指定できる。どんなパスワードポリシーにも対応 |
| 3 | **安心感** | 広告なし・データ収集は最小限（アナリティクスのみ）・強度が可視化されている |

## 利用シーン

```
1. 社内システムのパスワード変更
   → 「英大文字・小文字・数字・記号を各1文字以上、12文字以上」のルールに対応
   → 記号は !@#$ のみ許可 → カスタム記号選択で対応
   → 生成 → コピー → 社内システムに貼り付け

2. 新しいWebサービスへの登録
   → Safari外のアプリ内ブラウザでApple純正が効かない
   → アプリを開いて即生成 → コピー → 貼り付け

3. 親にパスワードを作ってあげる
   → 紛らわしい文字を除外して生成
   → 「このパスワード、3兆年かかっても破られないよ」と見せて安心させる
   → 親が紙に控えても読み間違えない

4. フリーランスの新規アカウント作成
   → クライアントツール（Slack, AWS 等）ごとに異なるルールに対応
   → 5件の候補から好きなものを選んでコピー
```

## 成功の定義

ユーザーが「使ってよかった」と思う瞬間：

- パスワードを考える手間がゼロになった時
- 面倒なパスワードルール（「記号は!@#のみ」等）に一発で対応できた時
- 紛らわしい文字が除外されて、メモしても読み間違えなかった時
- 強度表示を見て「このパスワードなら安全だ」と安心できた時
- 前回の設定が残っていて、開いてすぐ使えた時

## AI への提案・実装時の指針

新機能やUI/UXを提案する際は、以下を確認すること：

| # | チェック項目 |
|---|-------------|
| 1 | **ターゲットの ITリテラシー（低〜中）に合っているか？** 専門用語を避け、直感的に操作できるか |
| 2 | **「速さ」を損なわないか？** 操作ステップが増える機能は慎重に検討する。1画面完結が原則 |
| 3 | **「柔軟さ」に貢献するか？** 様々なパスワードポリシーへの対応力が上がるか |
| 4 | **「安心感」を維持しているか？** プライバシー・セキュリティの信頼を損なわないか |
| 5 | **既存の競合アプリとの差別化に貢献するか？** 競合がすでに解決済みの課題に工数をかけていないか |
| 6 | **MVPの目的（実績づくり・ASO経験値）に沿っているか？** 過度に凝った機能は避ける |

### UI/UX 判断基準

| 判断軸 | 方針 |
|--------|------|
| デザインテイスト | iOS ネイティブに馴染む Cupertino デザイン。独自のブランドカラーは最小限 |
| 情報量 | 1画面に収まる範囲で必要十分。スクロールは最小限に |
| 操作ステップ | 「開く → 生成済み → コピー」が最短フロー。設定変更は任意 |
| テキスト | 短く、平易な日本語。「エントロピー」ではなく「パスワードの強さ」と表現する |
| エラー表示 | 何が問題で、どうすれば解決するかを明示する（例: 「文字種を1つ以上選んでください」） |

## 技術的制約

| 項目 | 制約 |
|------|------|
| **フレームワーク** | Flutter / Dart（Cupertino ウィジェット使用） |
| **乱数生成** | `Random.secure()` を使用。暗号学的に安全でない乱数（`Random()`）は使用禁止 |
| **データ保存** | 生成されたパスワードはアプリ内に保存しない。設定値は Firestore（`settings` コレクション）に保存 |
| **ネットワーク通信** | Firebase Analytics のイベント送信のみ。パスワード文字列は一切送信しない |
| **プライバシーラベル** | Firebase Analytics の収集データに応じた申告が必要（「アナリティクス」カテゴリ） |
