## 2. ターゲットユーザー

### メインターゲット
App Storeで「パスワード生成」と検索するユーザー。Apple純正のパスワード自動生成では対応できない場面（ブラウザ外での利用、文字種の細かい指定、紛らわしい文字の除外など）で、サッと使える軽量ツールを求めている層。

### ユーザー像の例
- 新しいWebサービスに登録するとき、自分でパスワードを決めたい人
- 社内システムなど「英大文字・小文字・数字・記号を各1文字以上含む」のような制約があるパスワードが必要な人
- 紙やメモ帳にパスワードを控えている非テック層（親世代など）

## 3. 競合調査サマリー（MVP設計の根拠）

### 既存アプリの共通弱点（レビューから抽出）

| 弱点 | 該当アプリ例 | MVPでの対応 |
|------|------------|------------|
| 広告がうるさい | Password Generator X | 広告なし（完全無料） |
| 設定が毎回リセットされる | Strong Password Maker 他多数 | 設定の自動保存 |
| 紛らわしい文字を除外できない | 大半のアプリ | 除外トグル搭載 |
| 特殊文字を個別に選べない | 大半のアプリ | カスタム記号選択 |
| パスワード強度がわからない | 日本語アプリ全般 | 強度インジケーター |
| UIが古い | 大半のアプリ | Cupertinoデザインでモダンなネイティブ風UI |

### 直接競合（日本語・パスワード生成特化）
- かんたんパスワード生成（Daiki Tsukuda）
- パスワード生成 - かんたんシンプル作成（Atsushi Ezaki）
- 強力パスワード生成（Codepaint Inc.）
- KeyForge

### 間接競合（差別化済み）
- Apple純正「パスワード」アプリ（iOS 18〜）→ Safari/アプリ内専用。単体生成ツールとしては使えない
- 1Password, Bitwarden 等 → 管理ツール。重い。ターゲットが違う

## 4. 機能要件

### 4.1 コア機能（MVP必須）

#### F-01: パスワード生成エンジン
- 文字数: CupertinoSlider で指定（4〜128文字、デフォルト16文字）
- 文字種トグル: 大文字(A-Z) / 小文字(a-z) / 数字(0-9) / 記号 の各ON/OFF
- 最低1つの文字種がONであること（全OFF時はエラー表示）
- 有効にした文字種から各1文字以上を必ず含める（例: 大文字と数字がONなら、生成結果に大文字・数字が各1文字以上含まれることを保証）
- アプリ起動時に保存済み設定（初回はデフォルト設定）で自動生成する（「生成する」ボタンは再生成用）
- 乱数生成は Dart の `Random.secure()` を使用（暗号学的に安全な乱数）

#### F-02: 紛らわしい文字の除外
- CupertinoSwitch 1つで以下を一括除外: `o O 0 l I 1 | ` ` ' "`
- デフォルト: OFF（除外しない）
- 競合アプリ「かんたんシンプル作成」のみが対応している差別化ポイント

#### F-03: 特殊文字のカスタム選択
- モーダルシートで記号選択UIを表示（メイン画面の「記号をカスタム選択」タップで開く）
- 「すべて選択」/「すべて解除」ボタン + チップグリッドで記号を個別にON/OFF
- 対象記号: `! @ # $ % ^ & * ( ) - _ = + [ ] { } ; : , . < > ? / ~ |`
- サイトごとに使える記号が違う問題を解決する実用機能

#### F-04: 設定の自動保存
- アプリを閉じても前回の生成設定を保持
- Firestore の `settings/{userId}` ドキュメントに保存（文字数、各トグル状態、カスタム記号選択。詳細は [data-model.md](data-model.md) 参照）
- 競合の半数以上が対応していない最大の差別化ポイント

#### F-05: ワンタップコピー
- 生成されたパスワードをタップでクリップボードにコピー
- コピー完了のフィードバック（触覚フィードバック + 視覚的確認）

#### F-06: 複数候補の一括生成
- メイン画面内の折りたたみセクション（「他の候補を見る ▼」タップで展開/収納）
- 展開時に5件の候補をリスト表示
- 各候補に個別のコピーボタン
- 再生成ボタンで全候補を一括リフレッシュ

#### F-07: パスワード強度インジケーター
- 生成されたパスワードのエントロピー（ビット数）を計算
- 強度レベル閾値: < 28bit: 弱い / 28〜35bit: 普通 / 36〜59bit: 強い / 60bit〜: 非常に強い
- 4分割セグメントバー + 強度テキストラベル（弱い → 普通 → 強い → 非常に強い）
- セグメントバーは段階に応じた色で表示（赤 → オレンジ → 黄 → 緑）
- 解読推定時間の表示（例: 「総当たりで解読するのに約3兆年」）。攻撃速度の前提: 10億回/秒（1×10⁹）
- 色 + テキスト + バー形状の3要素で伝達（HIG アクセシビリティ準拠）
- 日本語アプリにはほぼ存在しない差別化機能

### 4.2 UI / UX 要件

#### U-01: Cupertino デザイン
- Flutter Cupertino ウィジェットベース（CupertinoPageScaffold, CupertinoSwitch, CupertinoSlider 等）
- ダークモード / ライトモード自動対応（CupertinoThemeData でシステム設定に追従）
- 1画面完結（タブやナビゲーションなし。設定もメイン画面内で完結）
- 日本語 / 英語のローカライズ対応（flutter_localizations + arb ファイル）

### 4.3 非機能要件

#### N-01: アナリティクス
- Firebase Analytics を導入
- 計測イベント例:
  - `password_generated`（生成回数）
  - `password_copied`（コピー回数）
  - `settings_changed`（設定変更の種類）
  - `app_opened`（起動回数）
- App Storeプライバシーラベル: Firebase Analytics の収集データに応じて「アナリティクス」を申告

#### N-02: セキュリティ
- 生成したパスワードはアプリ内に保存しない（クリップボードコピーのみ）
- パスワード文字列を Firebase に送信しない（イベント名と回数のみ）

#### N-03: パフォーマンス
- アプリ起動から生成可能状態まで1秒以内
- パスワード生成処理は即時（体感遅延なし）

## 6. ASO戦略（App Store最適化）

### キーワード設計
- メインキーワード: 「パスワード生成」「パスワード作成」
- サブキーワード: 「パスワード ランダム」「パスワード 自動生成」「password generator」
- タイトル例: 「パスワード生成 - 安全なパスワードをワンタップで作成」
- サブタイトル例: 「広告なし・オフライン対応」

### スクリーンショット訴求ポイント（優先順）
1. 「広告なし。完全無料。」
2. 「紛らわしい文字を自動除外」
3. 「パスワードの強度が一目でわかる」
4. 「設定を自動保存。毎回の設定不要」

### レビュー獲得
- 3回目の生成完了時に `in_app_review` パッケージでレビュー依頼（控えめに1回だけ）
